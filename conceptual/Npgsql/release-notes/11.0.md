# Npgsql 11.0 Release Notes

Npgsql 11.0.0 is available on [NuGet](https://www.nuget.org/packages/Npgsql/11.0.0).

Synchronous I/O remains supported and requires no configuration change.

## What's new

* `BeginTransaction()` and `BeginTransactionAsync()` accept `NpgsqlTransactionOptions.ReadOnly` and `Deferrable`, so you can set these options without a separate `SET TRANSACTION` command. `Deferrable` only takes effect for serializable, read-only transactions ([#6629](https://github.com/npgsql/npgsql/pull/6629)).
* Additional PostgreSQL OID alias types, such as `regclass` and `regtype`, can be read as `uint`, including in arrays. When writing a parameter, set `DataTypeName` to the PostgreSQL type (for example, `regclass`) instead of relying on inference ([#6503](https://github.com/npgsql/npgsql/pull/6503)).

See the [11.0.0 milestone](https://github.com/npgsql/npgsql/milestone/132?closed=1) for the full list of issues.

## Breaking changes

### .NET 10 or later is required

Npgsql 11 no longer targets .NET 8 or .NET 9. To upgrade to Npgsql 11, retarget your application to .NET 10 or later ([#6358](https://github.com/npgsql/npgsql/pull/6358)).

### Dependency injection is now part of Npgsql

The `Npgsql.DependencyInjection` package was merged into `Npgsql`. Remove the separate package reference when upgrading. Existing calls to `AddNpgsqlDataSource()` and related methods continue to work from the `Microsoft.Extensions.DependencyInjection` namespace, except for previously obsolete overloads, which have been removed. See [dependency injection setup](../diagnostics/logging.md#aspnet-and-dependency-injection) ([#6594](https://github.com/npgsql/npgsql/pull/6594)).

### Removed multiplexing

The experimental multiplexing mode has been removed. It could increase throughput for some workloads but did not scale well with high concurrency on machines with many CPU cores. Remove `Multiplexing` and `Write Coalescing Buffer Threshold Bytes` from your connection strings, even if multiplexing was disabled, and remove any assignments to the corresponding connection string builder properties. Regular connection pooling is unchanged ([#6457](https://github.com/npgsql/npgsql/pull/6457)).

### Removed deprecated large object APIs

`NpgsqlLargeObjectManager` and `NpgsqlLargeObjectStream`, obsolete since Npgsql 8.0, have been removed. Use PostgreSQL's [large object functions](https://www.postgresql.org/docs/current/lo-funcs.html) directly. For example, `lo_get` and `lo_put` read and write byte ranges. If you use `lo_open` to obtain a descriptor, use it on the same connection and within the same transaction. Existing large objects do not need to be migrated ([#6493](https://github.com/npgsql/npgsql/pull/6493)).

### Application Name can change pool metric labels

If you set `Application Name` in your connection string without explicitly naming the data source, Npgsql 11 uses that application name rather than the connection string as the `db.client.connection.pool.name` metric tag. Update dashboards that filter on the old label, or set `NpgsqlDataSourceBuilder.Name` explicitly to control the label and distinguish pools with the same application name. See [metrics](../diagnostics/metrics.md) ([#6533](https://github.com/npgsql/npgsql/pull/6533)).
